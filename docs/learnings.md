# Lessons and next questions

## What the project taught

**Applicability is part of correctness.** A rule can be calculated perfectly and
still be wrong for the instrument being screened. Framework eligibility must be
visible and tested alongside the formula.

**An unknown input needs its own state.** Missing earnings or price evidence is
not a favorable observation. Required unknowns block candidate status, and
unavailable instruments remain reachable in the interface.

**Dates explain what a number means.** A market session, fetch time and scan time
answer different questions. Updating a default view cannot silently relabel the
evidence in an older run.

**A cleaner UI still needs the details.** Removing duplicated navigation and
collapsing routine provenance improved the reading hierarchy. The evidence,
warnings, keyboard access and focus return still had to work.

**AI-assisted delivery needs reviewable boundaries.** A worker finishing, a test
passing, an owner accepting a change, a merge and a local installation are
different milestones. Recording those distinctions helped preserve truthful
handoffs.

**Portability is demonstrated by recovery.** Startup instructions alone did not
complete local acceptance. Real restart persistence and isolated restore checked
that the research record could survive operational changes.

## Questions for future work

- Can a private hosted version preserve the same explicit refresh and immutable
  research record while keeping owner-only access?
- How does the working interface behave on actual Safari, iPhone and iPad devices?
- What separate data, definitions and acceptance checks would contract-level
  options research require?
- What observed user study would establish whether the workflow improves research
  consistency or saves time?

These are open questions, not promised features. Automatic trading and measured
investment performance are outside the delivered beta.
